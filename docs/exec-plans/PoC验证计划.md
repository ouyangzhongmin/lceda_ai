# PoC 验证计划

## 1. 计划目标
- 在正式进入大规模实现前，用最小原型验证所有 P0 阻塞项。

## 2. 验证范围
- 双端插件运行
- 原理图读取
- 对象定位
- 草案落图
- 浏览器登录闭环
- 自定义配置本地存储
- `MCP` / Tool / Skill 可行性

## 3. 验证任务列表

### POC-01 最小插件运行
- 目标：
  - 验证标准版与专业版都能导入并运行最小插件
- 输出：
  - 最小插件截图
  - 运行结论
- 推荐脚本：
  - `npm run poc:host-probe`.
- 成功标准：
  - 双端均可打开插件 UI

### POC-02 原理图读取
- 目标：
  - 验证插件可读取当前原理图 source / JSON
- 输出：
  - 测试工程导出样例
  - 字段可用性记录
- 推荐脚本：
  - `npm run poc:host-probe`.
- 成功标准：
  - 能提取器件、网络、引脚、属性

### POC-03 对象定位
- 目标：
  - 验证问题项可定位到元件/网络/引脚
- 输出：
  - 定位测试记录
- 推荐脚本：
  - `npm run poc:host-probe`.
- 成功标准：
  - 能从列表跳转并聚焦对象
- 当前进展：
  - 已完成“规则结果 -> `issues.locate_first` -> `editor.locate`”的最小脚本化定位闭环。
  - 当前仍待真实嘉立创宿主环境验证实际聚焦行为。

### POC-04 最小落图
- 目标：
  - 验证程序化放置器件、创建连线、撤销行为
- 输出：
  - 空白页落图结果
- 成功标准：
  - 能完成最小草案落图

### POC-05 浏览器登录闭环
- 目标：
  - 验证浏览器打开、服务端 `login_session`、插件轮询状态同步
- 输出：
  - 登录流程录屏或截图
- 推荐脚本：
  - `PROBE_OPEN_EXTERNAL=1 PROBE_URL=https://lceda.cn/ npm run poc:host-probe`.
- 成功标准：
  - 登录后插件能自动进入已登录状态
- 当前进展：
  - 已完成“服务端 `login_session` + 插件轮询 + 邮箱验证码校验 + token 交换”的脚本化闭环验证。
  - 当前剩余真实宿主验证项为：插件内打开系统浏览器能力。

### POC-06 本地配置持久化
- 目标：
  - 验证自定义 LLM 配置可保存在插件本地
- 输出：
  - 重启后配置恢复验证结果
- 成功标准：
  - 本地配置可恢复

### POC-07 MCP / Tool / Skill 最小链路
- 目标：
  - 验证插件端最小 Agent 编排可调用工具，并可加载最小 Skill
- 输出：
  - 一次最小 ReAct 执行链路记录
- 成功标准：
  - 工具调用成功，Skill 能参与任务执行
- 当前进展：
  - 已完成最小 `ReAct` 编排与工具调用验证。
  - 当前 `Skill` 仍停留在文档约束层，尚未进入真实插件运行时装载验证。

## 6. 失败判定
以下任一项失败，需暂停正式开发并回到方案修正：
- 双端插件无法稳定运行
- 无法读取原理图核心数据
- 无法做对象定位
- 无法打通浏览器登录闭环

## 7. 产出要求
- 每个 POC 都需形成：
  - 结论
  - 截图或日志
  - 风险等级
  - 是否阻塞 P0
