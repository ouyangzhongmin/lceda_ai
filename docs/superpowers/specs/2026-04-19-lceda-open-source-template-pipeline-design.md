# 嘉立创开源原理图模板抽取与 RAGFlow 导入设计

## 背景

当前草案补全已经具备两部分能力：

- 插件侧已经可以消费 `external_rag_template_corpus`
- 服务端已经能在缺少结构化模板时，用启发式规则补出部分常见外围组合

这条链路解决了“前后端接不住模板数据”的问题，但它仍然不是最终目标。根本问题在于：

- 当前导入 RAGFlow 的知识大多是官方资料、培训文档和说明文本
- 这些文本更适合做设计知识检索，不适合直接产出可复用的子电路模板
- 继续靠手工启发式补更多外围组合，边际收益会快速下降

因此，下一阶段的主线应从“手写更多外围模板规则”切换为“抓取嘉立创开源原理图并抽取结构化模板”。

## 目标

- 从嘉立创开源项目中抓取适合模板化复用的原理图参考项目
- 优先获取可解析的原理图文件，详情页文本作为兜底输入
- 从项目中抽取结构化子电路模板，而不是整图复制
- 将模板产物导入 RAGFlow，让检索直接返回模板型数据
- 与现有插件侧 `external_rag_template_corpus` 消费接口保持兼容

## 非目标

- 首版不做大规模稳定调度、增量同步、分布式爬取
- 不尝试抽取所有类型的模拟/射频/高速复杂模块
- 不追求首版就完整还原整张开源原理图
- 不替代现有官方知识抓取流水线

## 设计结论

采用 `项目抓取层 + 模板抽取层 + RAGFlow 导入层` 的独立并行管线。

这条管线与现有“官方知识文档抓取”分离，避免互相污染；最终在服务端检索层聚合输出。

核心策略如下：

1. 使用“分类页优先、关键词补漏”的混合入口抓取嘉立创开源项目
2. 每个项目优先尝试定位并下载原理图文件
3. 若拿不到原理图文件，则退回详情页文本与元数据做低置信度抽取
4. 抽取目标是子电路模板，不是整图
5. 模板统一输出为 `external_rag_template_corpus` 兼容格式
6. 将结构化模板作为独立数据集导入 RAGFlow
7. 现有启发式规则仅作为 fallback，不再作为主路径扩展

## 方案对比

### 方案 A：继续扩启发式模板

优点：

- 实现快
- 风险低
- 与现有服务端路径兼容

缺点：

- 很快会变成大量硬编码规则
- 覆盖新器件和组合时维护成本高
- 无法真正吸收嘉立创开源项目中的结构化经验

### 方案 B：只抓详情页文本并抽模板

优点：

- 抓取实现较快
- 不依赖文件下载

缺点：

- 本质仍然偏文本启发式
- 很难稳定抽出完整网络和器件组合
- 模板置信度上限较低

### 方案 C：原理图文件优先，详情页兜底

优点：

- 最符合后续结构化模板抽取需求
- 即使文件获取失败，也能保留低置信度 fallback
- 能在首版就统一抓取输入模型

缺点：

- 首版工程量高于纯文本抓取
- 需要先解决项目详情与文件定位

推荐方案为方案 C。

## 总体架构

### 1. 项目抓取层

输入来自分类页和关键词入口，输出为统一的项目记录。

每个项目记录至少包含：

- `project_id`
- `title`
- `project_url`
- `tags`
- `summary`
- `preview_assets`
- `schematic_file_url`
- `raw_page_html`
- `source_mode`

其中：

- `schematic_file_url` 可为空
- `source_mode` 标识本项目是否拿到了原理图文件

抓取层不负责模板识别，只负责尽可能完整、稳定地收集项目原始输入。

### 2. 模板抽取层

模板抽取层统一接收两类输入：

- 原理图文件输入
- 详情页文本输入

抽取策略：

- 文件输入为主路径，产生高置信度模板
- 文本输入为 fallback，产生低置信度模板

抽取结果统一映射为模板记录，而不是把网页正文直接灌入检索索引。

### 3. RAGFlow 导入层

将模板记录转换为适合 RAGFlow 的导入格式。

保留两类信息：

- 检索所需的标题、正文、标签
- 模板所需的结构化字段

导入时与现有官方知识库分离，建议使用模板型专用 dataset。

## 数据模型设计

### 抓取产物模型

建议保存为原始 JSONL：

- `project_id`
- `title`
- `project_url`
- `category`
- `keywords`
- `summary`
- `tags`
- `preview_assets`
- `schematic_file_path`
- `schematic_file_url`
- `raw_page_html_path`
- `raw_page_text`
- `captured_at`

### 模板产物模型

模板字段对齐现有插件消费格式：

- `template_id`
- `template_type`
- `anchor_device_family`
- `anchor_device_model`
- `scenario_tags`
- `components`
- `pin_bindings`
- `default_values`
- `source`
- `quality_score`

其中 `source` 增加以下区分：

- `lceda_open_source_extract`
- `text_heuristic_fallback`

### 置信度策略

高置信度模板来源：

- 原理图文件可解析
- 网络与器件组合完整
- 模板类型可明确识别

低置信度模板来源：

- 只有详情页文本
- 只有器件关键词和接口描述
- 组合关系依赖启发式猜测

要求：

- 高置信度模板可直接进入自动补全候选
- 低置信度模板默认只作为弱候选或建议项

## 抓取策略设计

### 分类页优先

先抓分类/聚合页，建立基础项目池。

目标是尽快拿到“模板型项目”而不是所有项目。

适合首版的原因：

- 噪声比纯关键词小
- 更容易集中在开发板、模块、电源等类型

### 关键词补漏

在基础项目池之上，用目标关键词扩展项目集合。

关键词补漏主要用于：

- 找到分类页漏掉的具体型号项目
- 找到一些更偏模块化的小系统

### 文件优先抓取

对每个项目详情：

1. 先定位是否存在原理图文件或可下载链接
2. 若存在则保存文件并标记为 `file_first`
3. 若不存在则保存详情页文本并标记为 `text_fallback`

## 模板抽取策略设计

### 原理图文件抽取

文件抽取是主路径，应优先围绕以下信息构建模板：

- 主控器件
- 电源网络
- 指示灯
- 复位/启动按键
- 调试/下载接口
- I2C/I2S/扩展排针

抽取原则：

- 以局部连接簇为单位抽，不抽整图
- 每个模板应围绕一个清晰功能单元
- 模板可重用、可去重、可与现有草案合并

### 文本兜底抽取

当文件缺失时，可根据以下信号生成低置信度模板：

- 标题中的主控型号
- 文本中的接口关键词
- 器件值关键词
- 网络/协议名

文本抽取的目标不是高精度还原，而是提供结构化弱候选。

建议新增产物目录：

- `results/lceda_open_source_raw/`
- `results/lceda_template_corpus/`
- `results/lceda_ragflow_import/`

建议新增脚本：

- `scripts/server/lceda_open_source_crawler.py`
- `scripts/server/extract_lceda_templates.py`
- `scripts/server/transform_lceda_templates_for_ragflow.py`

## 最小实现范围

首版只实现：

1. 嘉立创开源项目列表与详情抓取
2. 原理图文件优先定位与保存
3. 统一项目记录输出
4. 模板抽取脚本骨架
5. 至少支持一批高价值模板类型的抽取
6. RAGFlow 导入格式转换
7. 对应单元测试

首版不实现：

- 多轮重试调度系统
- 增量更新任务系统
- 后台数据库持久化
- 全站级别大规模抓取

## 错误处理

抓取失败时：

- 记录项目详情页是否可访问
- 记录原理图文件是否缺失
- 保留可用文本信息，不直接丢弃项目

抽取失败时：

- 记录失败原因
- 不生成无意义模板
- 保持原始项目记录，便于后续重跑

## 测试策略

首版测试至少覆盖：

- 抓取产物记录结构稳定
- 文件优先、文本兜底逻辑正确
- 模板输出字段完整
- RAGFlow 转换格式与现有导入器兼容
- 低置信度模板能被显式标记

## 实施顺序

推荐顺序：

1. 定义抓取产物模型与目录
2. 实现 `lceda_open_source_crawler.py`
3. 实现 `extract_lceda_templates.py`
4. 实现 `transform_lceda_templates_for_ragflow.py`
5. 验证首批项目样本与模板质量
6. 再决定是否把新 dataset 聚合进服务端检索层

## 风险与缓解

风险一：站点结构复杂，首版难以稳定拿到原理图文件

缓解：

- 文件优先但允许文本兜底
- 抓取层与抽取层解耦，避免某类入口失败导致整管线不可用

风险二：原理图文件格式复杂，首版解析成本超预期

缓解：

- 先把抓取与统一记录打通
- 抽取器先面向最常见格式和最小模板集合

风险三：文本兜底模板噪声过高

缓解：

- 低置信度模板显式标记
- 默认只进入弱候选，不直接自动应用

## 结论

下一阶段的正确主线不是继续堆服务端启发式，而是建设“嘉立创开源项目抓取 + 原理图模板抽取 + RAGFlow 导入”这条独立数据管线。

这样做的收益是：

- 真正把真实参考设计沉淀为可复用模板
- 降低 LLM 自行发明外围组合的比例
- 让当前已经完成的 `external_rag_template_corpus` 消费链路发挥真实价值
