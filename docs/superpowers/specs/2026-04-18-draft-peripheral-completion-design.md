# 草案外围补全设计

## 背景

当前草案生成主要依赖 LLM 输出核心器件与主连接关系，容易遗漏接近可打样所需的配套电阻、电容、时钟、上拉下拉、接口基础保护和电源去耦。仅靠提示词增强不稳定，且不同模块的外围器件要求具有明显规律性，适合由插件侧规则补全。

## 目标

在草案生成完成后、预览与应用前，增加一层“外围补全器”，对已识别模块自动补充接近可打样的常见外围器件和基础网络连接，减少用户手工补件成本。

## 非目标

- 首版不做完整 ERC 级设计闭环，不自动保证所有器件数值均为最终生产定值。
- 不尝试一次覆盖所有芯片和所有模拟前端。
- 不在应用阶段临时派生新器件，避免预览与应用结果不一致。

## 总体方案

采用“规则驱动补全”为主、LLM 原始草案为辅的方案。

流程如下：

1. LLM 先生成核心草案。
2. 插件侧识别草案中的功能模块。
3. 外围补全器按模块模板追加缺失器件、引脚、网络与必要属性。
4. 预览展示补全后的完整草案，并明确哪些器件为自动补全。
5. 后续器件选型、应用布局、部分连线逻辑继续复用现有流程。

## 模块识别

首版采用启发式识别，不依赖新增模型调用。

识别来源：

- `component.ref`
- `component.name`
- `properties.device_name`
- `properties.preferred_search_query`
- 已有网络名和引脚名

首版识别模块：

- `esp32_s3_controller`
- `usb_c_power_input`
- `li_battery_power_path`
- `charger_power_stage`
- `ldo_regulator_stage`
- `i2s_mic_stage`
- `max98357a_amp_stage`
- `indicator_led_stage`
- `button_input_stage`
- `hall_sensor_stage`

## 外围模板

每个模板包含：

- 触发条件
- 新增器件定义
- 推荐默认数值
- 与原草案对象的连接规则
- 生成的网络名约定
- 去重规则

### ESP32-S3 控制器模板

补全内容：

- `3V3` 主电源去耦电容组：`10uF + 1uF + 0.1uF`
- `EN` 上拉电阻
- `EN` 到地复位按键位
- `GPIO0/BOOT` 上拉和到地启动按键位
- 若未检测到时钟器件，则补 `40MHz` 晶振及两侧负载电容

### USB-C 供电入口模板

补全内容：

- `CC1/CC2` 下拉电阻
- `VBUS` 输入滤波电容
- `VBUS` 基础 ESD/保护占位器件

### 锂电与充电模板

补全内容：

- 充电输入输出电容
- 电池端基础滤波电容
- 电源状态指示 LED 与限流电阻

### LDO 模板

补全内容：

- 输入电容
- 输出电容
- 若有使能脚则补默认上拉

### I2S Mic 模板

补全内容：

- 本地去耦电容
- 必要模式脚上拉下拉占位

### MAX98357A 功放模板

补全内容：

- 电源去耦电容
- 关键配置脚默认上拉下拉
- 扬声器输出端子占位

### LED / 按键 / 霍尔模板

补全内容：

- LED 限流电阻
- 按键上拉电阻
- 霍尔输出上拉电阻
- 传感器本地去耦

## 去重与冲突处理

外围补全前先检查：

- 同功能器件是否已存在
- 同名网络是否已存在
- 同一主芯片旁是否已有明显等价的去耦或上拉/下拉器件

处理原则：

- 已存在等价器件则跳过补全，不重复新增
- 已存在网络则挂接到既有网络
- 若仅缺少数值/属性，则补属性，不重建器件

## 数据模型扩展

新增或扩展的草案字段：

- `component.properties.generated_by = "llm" | "rule_completion"`
- `component.properties.completion_template = "<template_id>"`
- `component.properties.completion_role = "<role>"`

预览层需能区分：

- 用户/LLM 核心器件
- 规则补全器件

## UI 与预览

预览中增加一段“自动补全外围”摘要：

- 新增外围器件数量
- 新增的关键类别
- 典型补全示例

对补全器件采用更清晰说明：

- “已自动补全 ESP32-S3 去耦网络”
- “已自动补全 USB-C CC 电阻”

## 与现有流程的集成点

集成位置建议：

- `draft_generate_plan` 之后
- `previewDraftPlan` 之前

这样可以保证：

- 预览看到的是最终补全后的草案
- 后续器件搜索、应用、布局都基于同一份草案

## 测试策略

需要覆盖：

- 单模块补全：ESP32-S3 / USB-C / LDO / MAX98357A
- 组合补全：ESP32-S3 + 电池 + USB-C + 音频
- 去重逻辑：已有电容/电阻时不重复补
- 预览摘要：能展示补全信息
- 应用结果：补全器件会参与布局与应用

## 风险

- 不同器件库命名风格不统一，模块识别可能漏判
- “接近可打样”属于强约束，首版模板覆盖不足时仍会缺外围
- 若模板过度激进，可能补出与用户意图不符的器件

## 首版边界

首版只实现高价值、可稳定识别的数字小系统外围补全，优先支持：

- ESP32-S3 语音/小智设备类
- USB-C 供电输入
- 锂电 + 充电 + LDO
- I2S 麦克风 + MAX98357A 功放
- 指示灯 / 按键 / 霍尔基础外围

后续再扩展到更多 MCU、无线、传感器与模拟模块。
