# 项目代码结构设计文档

## 1. 文档目标
- 定义插件端与 Go 服务端的推荐代码目录结构。
- 为后续建仓、PoC、模块拆分和协作开发提供统一落地方式。

## 2. 结构原则
- 插件端与服务端分离，职责清晰。
- 共享协议优先通过文档与生成类型保持一致，不强依赖单仓共享代码。
- 首版优先支持快速落地，不做过早微服务拆分。

### 4.1 插件端模块职责
- `agent/`
  - ReAct 编排、Skill、Tool、MCP 适配
- `editor/`

  - `host/` 用于宿主桥接接口与运行时能力检测

- `storage/`
  - 本地配置、登录态、自定义 LLM 配置

## 8. 首版实现建议

### 8.1 插件端优先级
1. `editor/`
2. `rules/`
3. `services/api-client/`
4. `agent/orchestrator/`
5. `ui/panels/`

补充说明：
- 当前插件端已加入 `editor/host/` 作为宿主桥接层。
- 后续对接嘉立创标准版与专业版真实 API 时，应优先把真实宿主能力适配到桥接层，再由 `editor/adapters/` 复用统一主流程。

### 8.2 服务端优先级
1. `transport/http/`
2. `usecase/auth/`
3. `repository/postgres/redis/`
4. `usecase/credits/`
5. `usecase/llm/`
6. `usecase/rag/`

## 9. 约束说明
- 首版不强求前后端共享 monorepo 类型生成链路，但接口字段必须与文档一致。
- 首版服务端坚持单体架构，不拆微服务。
- 首版插件端优先保障可运行与可验证，不做过度 UI 抽象。
