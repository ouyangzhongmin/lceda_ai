## 2. 设计目标
数据库设计目标如下：
- 支持个人用户账户体系。
- 支持邮箱登录、微信登录绑定和浏览器登录会话。
- 支持 Credits 余额与不可变账本。
- 支持 LLM、RAG、Agent 任务审计。
- 支持知识文档元数据与 Qdrant 索引联动。
- 为未来团队/租户扩展预留字段，但首版不启用。

## 3. 数据存储分工

### 3.1 PostgreSQL
用于存储：
- 用户账户与认证关系
- 登录会话与 refresh token
- Credits 余额与账本流水
- 模型调用记录
- Agent 任务记录
- 知识文档元数据
- 配置与审计日志

### 3.2 Redis
用于存储：
- 邮箱验证码
- `login_session` 状态
- 一次性 `exchange_token`
- 限流计数
- 短期缓存

### 3.3 Qdrant
用于存储：
- 文档切片向量
- 检索 payload 元数据

## 4. 命名与约定
- 主键类型：`bigserial` 或 `uuid`
- 外部展示 ID：建议使用字符串业务 ID，如 `usr_xxx`、`ls_xxx`
- 时间字段：
  - `created_at`
  - `updated_at`
- 软删除字段：
  - `deleted_at`，仅在必要表使用
- 首版保留扩展字段：
  - `tenant_id`
  - `extra`

## 5. 核心表设计

### 5.1 users
用途：
- 用户主表

关键字段：
- `id` `bigserial` PK
- `user_uid` `varchar(64)` UNIQUE
- `display_name` `varchar(100)`
- `avatar_url` `text`
- `email` `varchar(255)` NULL
- `email_verified` `boolean`
- `user_type` `varchar(32)` default `personal`
- `status` `varchar(32)` default `active`
- `tenant_id` `varchar(64)` NULL
- `extra` `jsonb`
- `created_at` `timestamptz`
- `updated_at` `timestamptz`

索引建议：
- `uk_users_user_uid`
- `idx_users_email`
- `idx_users_status`

### 5.2 user_auth_identities
用途：
- 用户登录身份映射

支持类型：
- `email`
- `wechat_unionid`
- `wechat_openid`

关键字段：
- `id` `bigserial` PK
- `identity_uid` `varchar(64)` UNIQUE
- `user_id` FK -> `users.id`
- `provider` `varchar(32)`
- `provider_subject` `varchar(255)`
- `provider_app_id` `varchar(128)` NULL
- `is_primary` `boolean`
- `verified` `boolean`
- `extra` `jsonb`
- `created_at` `timestamptz`
- `updated_at` `timestamptz`

约束建议：
- `provider + provider_subject` 唯一

### 5.3 auth_login_sessions
用途：
- 浏览器登录会话

关键字段：
- `id` `bigserial` PK
- `login_session_uid` `varchar(64)` UNIQUE
- `user_id` FK -> `users.id` NULL
- `client_type` `varchar(32)`
- `plugin_channel` `varchar(32)`
- `plugin_version` `varchar(32)`

- `status` `varchar(32)`
- `poll_token_hash` `varchar(255)`
- `exchange_token_hash` `varchar(255)` NULL
- `login_methods` `jsonb`
- `expires_at` `timestamptz`
- `completed_at` `timestamptz` NULL
- `cancelled_at` `timestamptz` NULL
- `created_at` `timestamptz`
- `updated_at` `timestamptz`

状态枚举：
- `pending`

- `failed`
- `expired`
- `cancelled`

索引建议：
- `uk_auth_login_sessions_uid`
- `idx_auth_login_sessions_status`
- `idx_auth_login_sessions_expires_at`

### 5.4 auth_refresh_tokens
用途：
- refresh token 持久化

关键字段：
- `id` `bigserial` PK
- `token_uid` `varchar(64)` UNIQUE

### 5.6 auth_wechat_bindings

- `idempotency_key` `varchar(128)` NULL

## 10. Redis 键设计

### 10.1 登录会话
- `auth:login_session:{login_session_uid}`
- 存储内容：
  - `status`
  - `user_uid`
  - `exchange_token`
  - `expires_at`

### 10.2 邮箱验证码
- `auth:email_code:{scene}:{email}`
- TTL 建议：`5 分钟`

### 10.3 限流
- `rate_limit:{scene}:{subject}`

## 11. Qdrant 与 PostgreSQL 对应关系
- `knowledge_documents.document_uid` 对应 payload 中的 `doc_id`
- `knowledge_document_chunks.chunk_uid` 对应 payload 中的 `chunk_id`
- `knowledge_documents.kb_type` 对应 payload 中的 `kb_type`
- `knowledge_documents.source_ref` 对应 payload 中的 `source_ref`

## 14. 设计说明
- 首版仅支持个人用户，但所有主表都预留 `tenant_id` 或 `meta/extra` 扩展空间。
- Credits 账本必须不可变，不能通过直接更新历史流水修正金额。
- 登录状态短期存 `Redis`，正式认证与审计存 `PostgreSQL`。
- 知识切片正文可存 PostgreSQL 以便审计与调试，向量检索结果以 `Qdrant` 为准。
