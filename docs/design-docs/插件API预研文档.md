# 嘉立创插件 API 预研文档

## 1. 文档目标
- 用于验证嘉立创 EDA 标准版与专业版插件能力是否满足本项目首版需求。
- 所有影响 P0 可行性的能力点都应在本文件中形成“验证项 -> 验证方法 -> 结果 -> 风险结论”闭环。

## 2. 预研范围
- 标准版插件运行环境
- 专业版插件运行环境
- 原理图对象读取能力
- 对象定位与选区能力
- 程序化落图能力
- 浏览器登录配套能力
- 本地存储能力
- `MCP` / 工具注册 / Skill 装载适配能力

## 3. 预研原则
- 所有结论必须区分标准版与专业版，不允许混写。
- 所有能力结论必须有最小 PoC 证明。
- 若能力不稳定，应按“不可依赖”处理，而不是默认可用。
- 插件代码结构上应保持“宿主桥接层”和“业务主流程”分离，避免真实 API 接线时污染 Agent 与规则主流程。

## 3.1 当前接线策略
- 当前插件端已实现宿主桥接约定：
  - 若运行时存在 `globalThis.LCEDA_HOST_BRIDGE`，则优先走真实宿主桥接。
  - 若不存在，则回退到 mock 适配器，保证 PoC 与单元验证可继续执行。
- 该策略的目的：
  - 在未拿到完整嘉立创 SDK/API 细节前，先稳定主流程。
  - 后续标准版与专业版可以分别做桥接实现，而不改 Agent、登录、规则与 UI 主逻辑。

## 4. 验证清单

### 4.1 插件最小运行验证
- 验证项：
  - 标准版是否可导入最小插件
  - 专业版是否可导入最小插件
- 验证方法：
  - 使用官方 SDK 创建最小扩展
  - 分别导入标准版与专业版
- 预期结果：
  - 插件可加载
  - 插件 UI 可显示
  - 插件基础命令可执行
- 结果记录：
  - 标准版：待验证
  - 专业版：待验证
- 风险结论：
  - 若任一端无法稳定运行，双端 P0 需重新评估

### 4.2 原理图读取能力
- 验证项：
  - 读取当前页面 source / JSON
  - 读取器件、引脚、网络、属性
  - 读取多页原理图上下文
- 验证方法：
  - 构造包含多页、跨页网络、复杂属性的测试工程
  - 调用插件 API 导出上下文
- 预期结果：
  - 能拿到结构化原理图数据
  - 数据字段足够支撑规则引擎与 Agent 上下文构建
- 结果记录：
  - 标准版：待验证
  - 专业版：待验证
- 风险结论：
  - 若缺失引脚/网络属性，部分规则只能降级实现
- 当前补充说明：
  - 当前最小规则引擎已采用“元件属性声明期望网络名”的方式实现接线标准检查 PoC。
  - 这意味着真实插件 API 至少需要稳定提供：
    - 元件属性
    - 引脚名称或引脚号
    - 引脚到网络的连接关系

### 4.3 选区与定位能力
- 验证项：
  - 获取当前选中对象
  - 按对象 ID 定位元件/网络/引脚
  - 高亮或聚焦对象
- 验证方法：
  - 在测试原理图中选中器件、网络、引脚
  - 调用定位 API 做双向验证
- 预期结果：
  - 支持从问题列表跳转到图中对象
- 结果记录：
  - 标准版：脚本化定位链路已验证，真实宿主待验证
  - 专业版：脚本化定位链路已验证，真实宿主待验证
- 风险结论：
  - 若不能稳定定位，问题列表的交互价值会明显下降
- 当前结论：
  - 已完成“规则问题 -> 定位目标 -> `editor.locate`”的最小链路。
  - 当前脚本化 PoC 中可自动定位首条可定位问题。
  - 真实嘉立创宿主是否支持稳定聚焦、高亮、跳转，仍需分别验证标准版与专业版。

### 4.4 程序化落图能力
- 验证项：
  - 放置器件
  - 创建连线
  - 命名网络
  - 批量应用与撤销
- 验证方法：
  - 用最小生成草案在空白页落图
  - 验证撤销、回退、重复执行行为
- 预期结果：
  - 可按草案生成图形对象
  - 可在失败时停止或回退
- 结果记录：
  - 标准版：待验证
  - 专业版：待验证
- 风险结论：
  - 若自动连线能力不足，首版只能做到草案 + 半自动辅助
- 当前补充说明：
  - 已完成“草案生成 -> 草案预览 -> `validate_draft` 校验”的最小脚本化链路。
  - 尚未进入真实程序化放置器件、创建连线和撤销验证。

### 4.5 浏览器登录配套能力
- 验证项：
  - 打开系统浏览器
  - 插件定时轮询服务端
  - 登录状态更新后刷新 UI
- 验证方法：
  - 使用本地模拟登录服务做 PoC
- 预期结果：
  - 浏览器打开成功
  - 插件 2-3 秒轮询稳定
  - 登录成功后 UI 能自动更新
- 结果记录：
  - 标准版：部分验证通过
  - 专业版：逻辑链路已验证，待真实插件环境验证
- 风险结论：
  - 若浏览器打开或轮询受限，登录方案需调整
- 当前结论：
  - 已完成“服务端 `login_session` + 插件轮询 + 邮箱验证码校验 + token 交换”的最小闭环验证。
  - 当前 PoC 在插件本地脚本环境中通过 `runPluginPoc.ts` 直接模拟插件侧轮询流程，服务端接口链路已跑通。
  - 尚未验证“真实嘉立创插件环境内拉起系统浏览器”的兼容性，因此本项暂不判定为完全通过。

### 4.6 本地存储能力
- 验证项：
  - 保存自定义 LLM 配置
  - 保存登录态
  - 保存 UI 本地偏好
- 验证方法：
  - 写入配置后重启插件验证
- 预期结果：
  - 数据可持久化
  - 插件可恢复状态
- 结果记录：
  - 标准版：存储抽象已实现，待真实宿主验证
  - 专业版：存储抽象已实现，待真实宿主验证
- 风险结论：
  - 若本地存储边界不清晰，需要限制敏感信息持久化
- 当前结论：
  - 已实现统一 `KeyValueStore` 抽象，并提供 `MemoryKeyValueStore`、`LocalStorageKeyValueStore` 两种实现。
  - 已实现登录态持久化 `PersistentSessionStore`。
  - 已实现自定义 LLM 配置本地存储 `CustomLlmConfigStore`。
  - 当前 Node PoC 中已验证“写入后可读取恢复”，但尚未在嘉立创真实插件宿主中验证存储生命周期。

### 4.7 流式响应能力
- 验证项：
  - HTTP 长连接
  - `SSE` 或近似流式输出
- 验证方法：
  - 调用测试流式接口，观察插件端表现
- 预期结果：
  - 可支持 LLM 流式返回
- 结果记录：
  - 标准版：待验证
  - 专业版：待验证
- 风险结论：
  - 若流式不稳定，首版应优先普通响应

### 4.8 MCP 与 Skill 适配能力
- 验证项：
  - 插件中是否适合承载 `MCP client`
  - 工具注册是否可动态加载
  - Skill 装载是否可行
- 验证方法：
  - 实现最小工具注册器与最小 Skill
  - 模拟一个 MCP 资源接入
- 预期结果：
  - Agent 编排器可稳定调用本地工具与扩展工具
- 结果记录：
  - 标准版：最小 Tool 链路已验证，Skill 待接入真实插件运行时
  - 专业版：最小 Tool 链路已验证，Skill 待接入真实插件运行时
- 风险结论：
  - 若动态装载不稳定，首版应限制为内置 Skill + 固定工具清单
- 当前结论：
  - 已完成最小 `ReAct Orchestrator + ToolRegistry + editor tools` 链路。
  - 当前 `ReactOrchestrator` 已可调用 `editor.get_current_context` 工具并产出上下文摘要。
  - 真实 `MCP client` 与外部 Skill 装载尚未进入插件宿主环境验证阶段。

### 4.9 RAG 与 LLM 代理联调能力
- 验证项：
  - 插件调用服务端 `rag.search`
  - 插件调用服务端 `llm.generate`
- 验证方法：
  - 使用本地 PoC 服务返回固定知识证据和固定模型结果
- 结果记录：
  - 标准版：脚本化联调已通过，真实宿主待验证
  - 专业版：脚本化联调已通过，真实宿主待验证
- 风险结论：
  - 已完成真实 `Qdrant` 与模型代理调用链路接入，但当前仍采用“失败回退到 PoC 实现”的可用优先策略
- 当前结论：
  - 插件侧已可通过 Tool 调用服务端 RAG 与 LLM 接口。
  - 服务端已具备 `VectorStore` / `LLM Provider` 抽象与可运行实现，当前配置可直接对接 Qdrant + 豆包/通义等 OpenAI 兼容模型接口。

## 7. P0 阻塞项判定
以下任一项不成立，都会阻塞首版正式开发：
- 双端最小插件不可运行

## 9. 当前 PoC 验证记录

### 9.1 服务端登录闭环
- 验证命令：
  - `BASE_URL=http://127.0.0.1:18081 node scripts/download/run-login-poc.mjs`
- 验证结果：
  - 已成功完成创建登录会话、查询状态、发送验证码、校验验证码、交换 token、刷新 token。

  - 服务端登录 PoC 主链路通过。

### 9.2 插件侧最小闭环

  - `loggedIn=true`
  - `channel=standard`
  - `components=2`
  - `nets=2`
  - `selection=1`
  - `summary=collected schematic context for schematic_analysis; plugin auth flow completed; user=demo@example.com`
- 结论：
  - 插件侧最小上下文采集、最小 ReAct、登录会话轮询与会话写入已通过脚本化验证。

### 9.3 宿主桥接注入链路
- 说明：
  - 插件启动会输出 `capability_report`，用于确认宿主能力是否就绪。
  - 当 `LCEDA_REQUIRE_HOST_BRIDGE=true` 且宿主未注入桥接对象时，插件会返回 `unimplemented` 适配器并显式报错。
- 验证命令：
  - `cd plugin && POC_USE_FAKE_HOST=1 BASE_URL=http://127.0.0.1:18082 npm run poc:plugin`
- 验证目标：
  - 验证插件在存在宿主桥接注入时，会优先走 `host` 通道而不是 mock adapter。
- 当前实现状态：
  - 已完成桥接接口、标准版/专业版桥接工厂、全局注入入口与 fake-host 模拟器。
  - 可用于后续替换为嘉立创真实宿主 API。
- 风险说明：
  - 当前 fake-host 只验证接线结构，不代表真实嘉立创 SDK/API 字段已经确认。

### 9.4 浏览器启动与轮询控制骨架

### 9.5 本地持久化 PoC
